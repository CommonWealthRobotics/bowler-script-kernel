# STEP test files

Fixtures for `junit.bowler.StepFileTest`, which round trips geometry through
`STEPFile` and loads files written by other tools. Tests run from the module
root, so the test refers to this directory as `testStepFiles`.

## Round trip fixtures

Written by `STEPFile` itself (via `GenerateRoundTripFixtures.java`), so loading
them proves an export survives a read:

| file | geometry | mesh | edges |
| --- | --- | --- | --- |
| `cuboid_export.step` | `Cube(10)` | 8 vertices, 12 triangles | 12 |
| `hole_export.step` | `Cube(20,20,4)` minus a sphere | 142 vertices, 200 triangles | 49 |
| `cylinder_export.step` | two unioned `Cylinder`s | 502 vertices, 856 triangles | 196 |

Regenerate with the module's classes on the classpath:

    java -cp <classes> GenerateRoundTripFixtures testStepFiles

## A meshed part with hard facets

`Pointer_Hand_star.3mf` is the source mesh of a hand, and
`Pointer_Hand_star.step` is `STEPFile`'s export of its first object. The mesh is
closed and watertight, but a kernel cut it out of its own geometry, so it stores
46 pairs of vertices less than a micron apart whose edges are shorter than the
file's own length precision. The export welds those vertices, keeps every
triangle, and groups triangles only when they lie in one plane, so the result
reads back as a single solid. The two annular faces the mesh genuinely has, at
z = 3.6 and z = 42.3, are written as an outer bound with a hole.

The fixture is regenerated by loading the 3mf and writing it out:

    java -cp <classes> ...  # new STEPFile(CSG.fromThreeMF(3mf).get(0)).write(step)

## A group of parts, written by an earlier export

`Charming_Troll_Group_of_3.3mf` is the source mesh of a group of three parts and
`Charming_Troll_Group_of_3.step` is an export of it. The STEP was written before
the writer distinguished a watertight mesh from an open sheet by its boundary
loops, so it declares `SHELL_BASED_SURFACE_MODEL`/`OPEN_SHELL` for a mesh that is
closed. A CAD importer then invents faces to close the shell, and reading the
file back yields geometry Manifold rejects as non-manifold. The file is kept as
the reproduction for `CharmingTrollStepRoundTripTest`, which exports the 3MF
again and requires the mesh to survive with identical points and indices.

`STEPFile` also writes a `TESSELLATED_SHAPE_REPRESENTATION` of each part,
related to its BRep, so a reader reproduces the source mesh exactly instead of
re-triangulating the planar faces.

## What the reader does not cover

* A curved face is not tessellated, so a solid whose faces are curved (a sphere,
  a torus, or the side of a cylinder) contributes its edges but no mesh. Faces
  that are planar, or faceted within their own loops, do tessellate. A planar
  face with holes is triangulated as an annulus, so the holes are not filled in.
* Assemblies are read with their placement transforms applied: each occurrence
  becomes its own shape in the file's world coordinates, and a file's colours
  come through on the shapes.
* A surface of revolution or extrusion is read from its edges only.
